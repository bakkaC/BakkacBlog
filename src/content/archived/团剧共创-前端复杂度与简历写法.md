# 团剧共创前端 —— 复杂度盘点与简历写法

> 面向简历准备的内部速查。第一部分穷举前端真正复杂的地方供挑选，第二部分给出可直接套用的简历文案（分档）。
> 一句话定位：**团剧共创是面向 TRPG 的多人实时协作平台，核心是把多人聊天流实时编译为可播放的视觉小说，并支持一键导出为可部署游戏包 / 视频工程。**

## 第一部分：前端复杂在哪里（供挑选）

### A. 核心难点 ——「聊天 → 视觉小说」实时增量编译引擎

整个项目工程复杂度的真正核心，也是区分"做了个聊天室"和"做了个系统"的关键点。

1. **自研流式 DSL 编译器**：`RealtimeRenderer` 是个 112KB 的单例类，把流式聊天消息实时编译成 WebGAL 视觉小说脚本（DSL），通过 WebSocket 推送到引擎预览。以 Space 为游戏单位、Room 为场景单位组织。
2. **三态增量重渲染策略**（最值得讲）：对每条消息变更计算 `none / self / suffix` 三种策略——内容指纹相同则跳过；普通对话只重渲自身；"有状态消息"（背景 / BGM / 立绘 / 特效 / 状态事件）变更必须从该点重编整个后缀。本质是"增量计算 + 脏标记传播"，为了在多人高频改消息时避免全量重建。
3. **行号映射 + 状态快照回放**：维护 `messageId → {startLine, endLine}` 行号范围，以及每条消息"执行后的房间状态快照"（立绘槽位、小头像可见性、战斗轮次、地图叠层、token 角色）。跳转到任意历史消息时能正确恢复整个舞台状态，或从某行裁剪重建。类内维护 20+ 个 Map 做缓存与状态。
4. **自定义 WebSocket 调试协议**：独立长连 + `DebugCommand` 协议（JUMP / SYNCFC / SYNCFE / EXE_COMMAND / TEMP_SCENE），带断线自动重连 + 离线消息队列缓冲。
5. **细节里的工程**：成对骰子消息在时间窗内延迟合并渲染；批量同步深度控制（何时 flush 到文件、何时跳到最新行）；模板版本标记机制（检测临时工程是否需要随模板升级重建）。

### B. 离线优先的消息同步层（分布式数据一致性味道）

6. **WASM SQLite 本地缓存**：用 sql.js 在浏览器里跑 SQLite 缓存聊天历史，"先展示本地快照、后台按 `syncId` 游标增量同步"，切房间不被网络阻塞。
7. **乐观更新 + messageId 别名链**：发消息时先用临时 ID 乐观回填，服务端返回真 ID 后做"临时 ID → 真 ID"替换（带 TTL、环检测）；tombstone 软删除；持久化乐观重复清理。WS 重连 / 页面可见性变化时触发增量补拉。处理"本地状态 vs 服务端状态最终一致"的经典难题。

### C. 渲染性能治理（贯穿全模块，最接地气，面试高频）

8. **Context → 细粒度 Zustand 迁移**：把高频 UI 状态从 React Context 迁出，拆成一堆细粒度 store，衍生 "FromStore" 轻订阅组件（只订阅自己关心的字段），从根上消除 `RoomWindow` 的级联重渲染。store setter 普遍做相等性短路返回。
9. **虚拟滚动 + 派生节点缓存**：react-virtuoso 处理数万条消息，按滚动位置回溯计算"当前应显示的背景 / 特效"，useMemo 缓存派生节点。
10. **抽屉宽度 / 开关独立 store**：拖拽调宽不触发主窗重渲染。React Compiler 自动 memo 化。

### D. 多目标编译产物（一套数据，三个输出）

同一套消息数据，共享底层编译核心（`spaceWebgalCompiler.ts`），输出三个完全不同的目标：

11. **实时预览**：增量、写引擎文件 + WS 推送。
12. **静态可部署游戏包**（`publishRenderer.ts`）：base64 内联资源、PWA manifest / icons、独立 loader.js，可直接部署到 Cloudflare Pages 当成品游戏。
13. **Premiere / FCP 视频工程导出**（`premiereExporter.ts`，35KB）：把聊天剧本编译成 `xmeml` 工程 XML（时间线、轨道、clip、TS 音轨），让用户把跑团记录拉进剪辑软件做视频。跨度大、有记忆点。

### E. 资源与媒体管线

14. **多级资源缓存与镜像**：CacheStorage 镜像远程资源、"已观测资源"预热、自有鉴权代理回退、原图 URL 回退候选链；并发上限控制批量预热 sprite / 背景 / BGM。
15. **动态立绘合成**：基于 variant + 裁剪上下文，把"基础立绘 + 表情差分图层"合成为最终立绘，用裁剪哈希做缓存键。
16. **浏览器内音频转码**：ffmpeg.wasm 把音频转 Opus，作为 TTS `-voice` 注入剧本（带并发去重缓存）。

### F. 编辑器类硬交互

17. **自研 contentEditable 富文本输入**：@提及作为不可编辑节点、图片粘贴、光标上下文提取（喂给 AI 补全）、文本样式语法、骰子 / 指令命令面板自动补全（`/r 1d20`、`/sc` SAN 检定）。contentEditable 本身就是公认难搞的领域。
18. **剧情流程图编辑器**：@xyflow/react + dagre 自动布局，做房间（场景）间的有向图编排，带条件分支、起止节点，最终编译进 WebGAL 场景跳转。
19. **双渲染引擎并存**：pixi.js 8 自研聊天内粒子特效层（雨 / 雪 / 樱花）+ WebGAL galgame 运行时。

### G. 架构与工程化

20. **跨端 Monorepo**：pnpm workspace，Web / Electron 桌面端 / RN-Expo 移动端三端，领域逻辑下沉到 `@tuanchat/domain`（含战斗状态机 state-runtime）、OpenAPI 自动生成 client、共享 query 包。
21. **前沿工具链**：Vite 8 / Rolldown、oxlint（Rust）、tsgo、React 19 + React Compiler，并自研构建脚本。

## 第二部分：简历怎么写

### 写法原则

- 简历不是讲全部，是讲"密度最高的 3-5 条"。上面 21 点里，**A / B / D 是差异化点**（让面试官"哦?"），**C 是面试官几乎必追问的硬通货**，F / G 是加分项。
- 每条用「做了什么 + 怎么做（技术名词）+ 量化 / 结果」结构，避免只写"负责 XX 模块"。
- 量化优先：数万条消息、20+ 类状态缓存、压缩率、重渲染减少比例等。没有真实数字就用规模词，**别编**。

### 简历 bullet 候选（分档挑选）

**第一梯队（差异化硬核，强烈建议至少选 1-2 条）**

- 设计并实现"聊天消息 → 视觉小说脚本"的**实时增量编译引擎**：基于内容指纹的三态（`skip / self / suffix`）脏标记策略，仅对受影响消息后缀重编译，在多人高频编辑场景下避免全量重建。
- 实现**行号映射 + 状态快照回放**机制，为每条消息维护"执行后舞台状态"（立绘 / 特效 / 战斗 / 地图），支持跳转到任意历史消息时精确恢复场景。
- 构建**离线优先的消息同步层**：浏览器内 WASM SQLite 本地缓存 + `syncId` 增量游标 + 乐观更新与临时 / 真实 messageId 别名链，实现切房间零等待与断线重连后的最终一致。
- 复用同一编译核心实现**三目标产物输出**：实时预览、可独立部署的静态游戏包（PWA + 内联资源）、Premiere `xmeml` 视频剪辑工程。

**第二梯队（性能 / 工程，面试常被追问，建议选 1 条压舱）**

- 通过将高频 UI 状态从 React Context 迁移至细粒度 Zustand store + 衍生轻订阅组件 + setter 相等性短路，消除聊天主窗的级联重渲染；配合 react-virtuoso 虚拟滚动支撑数万条消息流畅滚动。

**第三梯队（加分，空间够再放）**

- 自研基于 `contentEditable` 的富文本输入器：@提及不可编辑节点、图片粘贴、光标上下文提取、骰子 / 指令命令面板自动补全。
- 维护 Web / Electron / RN-Expo **三端 Monorepo**，将战斗状态机等领域逻辑下沉至共享包，统一 OpenAPI client 与数据查询层。
- 落地前沿工具链（Vite 8 / Rolldown、oxlint、tsgo、React 19 + React Compiler），并自研构建脚本。
- 实现 CacheStorage 资源镜像 + 鉴权代理回退 + 并发预热的媒体管线，及 ffmpeg.wasm 浏览器内音频转码。

### 不同岗位的取舍建议

| 目标岗位 | 主推 |
| --- | --- |
| 大厂 / 基础架构 | 第一梯队「增量编译」「离线同步一致性」+ 第二梯队性能（最像系统设计能力） |
| 业务前端 / 中小厂 | 「实时联动效果 + 三目标导出 + 性能优化」（故事性强、好演示） |

**一句话定位**
团剧共创前端可以写成：一个面向 TRPG/互动叙事的实时协作创作平台，负责 Web、Electron、Expo 移动端多端体验，核心包括多空间多房间聊天、角色扮演、富媒体消息、文档化消息编辑、WebGAL 实时预览、AI 图像生成与本地缓存/同步体系。

**主要复杂点**
1. 实时聊天状态复杂：房间消息、私聊消息、未读数、已读线、WebSocket 增量同步、React Query 缓存失效、本地乐观更新需要保持一致。
2. 消息模型复杂：文本、图片、音频、视频、文件、骰子、状态事件、WebGAL 选择项、背景/BGM/特效等多种消息类型共用同一条消息流。
	1. TRPG 领域规则复杂：角色、立绘、KP/玩家权限、暗骰可见性、状态指令、先攻、地图、线索夹等不是普通 IM 的模型。
3. 长列表性能复杂：聊天记录使用 `react-virtuoso` 虚拟滚动，还要处理自动滚底、未读提示、当前可见索引、媒体消息 overscan、筛选、多选、导出、转发。
4. 消息顺序和增量同步复杂：代码里按 `position / syncId / messageId / createTime` 排序，并处理 sync gap、删除态 tombstone、重复消息合并。
5. 富文本/块编辑器复杂：`MessageEditor` 不是普通 textarea，而是块级消息编辑器，支持文本块、媒体块、斜杠菜单、角色/立绘选择、跨块选择、拖拽排序、撤销重做、本地保存和远端 patch。
6. 文档与聊天融合复杂：聊天消息可以以文档/剧本编辑体验组织，并通过 patch 操作映射回房间消息流。
7. WebGAL 实时渲染复杂：聊天消息要编译成 WebGAL 脚本，按 Space 创建游戏、按 Room 创建场景，支持历史导入、增量重渲染、跳转到消息、背景/立绘/BGM/音效/骰子/分支。
8. 资源处理复杂：头像、立绘、背景、地图、视频、音效、小头像、TTS 语音等需要上传、缓存、命名、复用和预热。
9. WebGAL 状态回放复杂：渲染器维护当前立绘、背景、小头像、战斗轮、地图 token、消息行号范围、消息渲染快照，支持从任意消息重新渲染后续内容。
10. AI 图像链路复杂：仓库包含 NovelAI client、提示词/参考图/inpaint/蒙版/历史记录/Token Meter 等 AI 作图工作台。
11. 缓存层复杂：React Query、共享 `@tuanchat/query`、`@tuanchat/domain`、移动端本地缓存、Web localStorage、本地 DB 包之间要避免多份业务真相。
12. 跨端复用复杂：Web 与 Expo Mobile 复用 OpenAPI client、domain、query，本地登录态、消息读取、附件发送、WebSocket 同步又要分端适配。
13. Electron 集成复杂：桌面端不仅包装 Web，还处理自定义协议、dev server 探测、单实例锁、通知跳转、自动更新、NovelAI 代理、WebGAL 进程 IPC。
14. 构建发布复杂：Web 部署到 Cloudflare Pages，Electron 产物支持 NSIS/zip、增量更新，移动端有 Expo/Android dev build 脚本。
15. 类型与接口复杂：OpenAPI 生成 client，前端还要 patch 结果守卫，业务失败和 HTTP 失败要分开处理。
16. 权限与身份复杂：空间成员、房间成员、角色权限、KP 权限、文档权限、归档空间、私聊模式混合在同一套路由和 UI 中。
17. UI 状态复杂：左侧空间/房间/文档树、右侧多抽屉、子窗口、移动端抽屉、路由参数、localStorage 偏好和 zustand store 互相影响。
18. 测试维护复杂：仓库有大量 domain/query/component/helper 测试，适合强调把复杂规则下沉为可测纯函数。
19. 工程治理复杂：单仓多应用 + 多 workspace package，要求边界清晰，不能把 Web 逻辑、移动端逻辑、领域规则混在一起。
